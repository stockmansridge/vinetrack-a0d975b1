
- Product-line rate priority (line rate → vineyard_preferred_rate → confirmed default_rates → label selection → manual) lives in src/lib/vineyardPreferredRate.ts + productLineFromChemical; why: one shared precedence matching iOS/Android.
- Chemical Inventory access uses four selected-vineyard role helpers in src/lib/chemicalInventory.ts (view/purchase/manage/costs), never System Admin; why: matches live SQL 262 RLS and mobile.
- Authoritative physical vine count (Dashboard, Blocks list, Block Detail, Yield blocks, Pruning Yield density, new Actual Yield metadata) uses authoritativeVineCount() in src/lib/paddockRowVines.ts: positive block override → COMPLETE row-effective total (mobile/SQL 263 row maths, partial totals rejected) → caller fallback; spray/irrigation/fertiliser/piece-rate keep deriveMetrics; why: iOS/Android/SQL 263 parity without changing calc contracts.
- Chemical Purchase/Inventory RPCs are the only purchasing/pricing authority; Edit Chemical omits purchase/pack_size/price_per_pack/pack_unit on save (omitLegacyPurchaseFields) and shows a read-only summary; why: avoid a second, stale pricing system.
- Spray chemical financial cost = quantity (Tank Actuals only when complete under the exact mobile `areSprayTankActualsComplete` identity/session/association rule, else planned) × SQL 264 chemical_season_purchase_prices, vintage = allocation season_year else trip date in the vineyard time zone; resolved in src/lib/chemicalCostResolver.ts and applied via useChemicalAllocationOverlay to Cost Reports and Work Task Reports alike as a display-only overlay; legacy line costPerUnit only when SQL 264 says season_purchase_cost_unavailable, never Saved Chemical pricing or names; why: iOS/Android parity and the purchase ledger is the only pricing authority.
- Fertiliser Calculator units derive from form+mode (per-vine ÷1000), saved-product cost comes only from SQL 264 season prices, stock from the Chemical Inventory summary RPC, and allocation removal from delete_fertiliser_record_allocation; why: iOS parity and a single pricing/inventory authority.
- Fertigation (Round 1) is a Program Step operation_type 'Fertigation' applied via irrigation: irrigation saves first through the unchanged record_irrigation_session RPC, then fertigation_applications is upserted against the returned session id with stable UUIDs (src/lib/fertigation.ts); gated to System Admin in UI and by sql/265 RLS/RPCs; why: one linked record, safe retries, and no leak to released mobile builds.
- Full Block Backup import never writes source ids: new blocks regenerate row/endpoint/polygon-point UUIDs; matched blocks keep destination row ids by physical row number (src/lib/paddockFullBlockBackup.ts); why: database rejects cross-vineyard row identity reuse and copies must be independent.
- Contour Row Mapping (Beta) drafts are stored only via get/save/discard_contour_row_mapping_draft (public SECURITY INVOKER wrappers over vt_contour_private definer functions; src/lib/contourRows/*, docs/contour-row-mapping-contract.md), System Admin + is_vineyard_member on live blocks, monotonic slot revision + draft identity + discard tombstones + content-hashed client save ids, Portal confirms only an exact read-back; never write paddocks.rows or other operational inputs and leave src/lib/paddockRowGeneration.ts untouched; why: review-only pilot that older mobile builds and existing calculations cannot see, with no stale write or resurrection.
- Contour Row Mapping map zoom beyond Apple's native clamp uses precision magnification in src/components/paddocks/ContourAppleMap.tsx (map rendered at 1/k size and CSS-scaled; all input then handled in-component via MapKit MapPoint maths on visibleMapRect); why: Apple clamps camera distance (~170 m) and CSS scaling alone would misplace clicks/drags.
- Normal Rows previews opt into the same ContourAppleMap precision renderer through BoundaryDrawMap.precisionPreview (readonly only; Esri fallback maxNativeZoom 19 / maxZoom 23). RowMapWorkspace moves a stable portal host for full screen and hides settings without unmounting; why: preserve map/field state while escaping AppLayout stacking, with dialogs above the map. Boundary editing, row generation, permissions and save payloads remain separate.
- Portal client telemetry is recorded only via the shared record_my_client_activity RPC as ('portal-web','web') from src/components/PortalActivityTracker.tsx (src/lib/portalClientActivity.ts), best-effort and signed-in only; why: one per-client activity ledger shared with iOS/Android, no Portal-only schema.
- Crew / External Contractors use public.vineyard_external_resources via src/lib/externalResources.ts and the shared ResourcePicker (members first, active same-vineyard externals second); Work Tasks write exactly one of assigned_to/assigned_external_resource_id; pruning keeps worker_or_crew as the name snapshot and sets typed ids only via set_pruning_activity_resource after the unchanged save RPC, only when explicitly changed; why: shared Rork schema, no Portal-only rules.
